Features

Everything you want from an SMTP recon tool, with the safety rails and politeness built in.

Fully asynchronous

Tokio-powered concurrency with bounded connections, per-operation timeouts and graceful Ctrl+C draining.

Session reuse (RSET)

One connection probes a whole batch of candidates. Dropped mid-batch? It reconnects and resumes from the exact failure.

Accurate verdicts

3-digit codes plus RFC 3463 enhanced status codes (5.1.1, 5.7.1, 4.7.1 …) classify each probe precisely.

Catch-all detection

Random UUID probes run before scanning; catch-all domains are flagged, and can be skipped entirely.

DNS & security recon

MX (null-MX aware), SPF and DMARC in every report, plus provider fingerprinting for 40+ platforms.

TLS everywhere

Opportunistic / required / disabled STARTTLS, implicit TLS on 465, and --insecure for legacy servers — pure-Rust crypto.

Greylist-aware

4xx replies are retried on your schedule; jittered pacing and connection caps keep you under the radar.

Four output formats

Human table, json document, streaming jsonl and csv — with an accepted-only filter.

How it works

A five-phase pipeline per domain — no email is ever delivered, the probe stops right after RCPT TO.

DNS reconMX sorted by preference, SPF, DMARC, provider guess
Catch-all probeRandom UUID local-parts test address harvesting
Candidate probingEHLO → STARTTLS → MAIL FROM → RCPT TO → RSET
ClassificationSMTP code + enhanced status code → verdict
Reporttable / json / jsonl / csv, streamed or written to file

Failing over between MX hosts, reconnecting dropped sessions, retrying greylisted candidates, and checking GitHub Releases for updates — all automatic.

Verdicts

Every candidate gets one of seven verdicts, derived from the 3-digit code and the RFC 3463 enhanced status code.

Verdict Trigger Meaning
accepted 250 / 251 Mailbox exists and accepts mail
accepted_catch_all 250 on a catch-all domain Accepted — but so is every other address
rejected 550 5.1.1 & friends User unknown / mailbox unavailable
temporary 4xx (421/450/451/452) Greylisted or rate-limited — try later
policy_blocked 5.7.x, 554, MAIL FROM rejection Anti-enumeration / blocklist policy
indeterminate 252 Cannot VRFY user, but will accept
error timeout / TLS / EOF Connection-level failure

Usage

A few practical recipes. Full reference with rcptx --help.

# HR + executive hunt across a domain list, JSON report of hits only
$ rcptx -D targets.txt -p hr,executive --only-accepted --format json -o hits.json

# Stream accepted addresses as CSV, plausible random sender, custom resolver
$ cat domains.txt | rcptx --stdin -l careers,people,ceo \
    --auto-mail-from --dns-server 1.1.1.1 --format csv

# Cautious scan of a hardened target: slow pacing, no catch-all waste, greylist retries
$ rcptx -d strict-corp.com -p all -c 1 --delay-ms 2000 --jitter-ms 800 \
    --max-rcpt-per-conn 3 --stop-on-catch-all --retry-greylist 2 --retry-delay 30

# DNS-only posture check — zero SMTP traffic
$ rcptx mx example.com --format json

# Check for a newer release (also available as --check-update before any run)
$ rcptx check-update

# Provider fingerprints: list the table, see which needle matched a domain
$ rcptx providers
$ rcptx mx example.com -v
